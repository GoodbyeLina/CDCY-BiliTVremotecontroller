# App 内诊断记录与导入/播放追踪（alpha.4）

## 原日志为什么不够用

旧日志主要记录“开始导入”或“手动播放”，缺少以下信息：

- 导入失败没有写入日志，解析步骤和网络异常随界面提示消失。
- 播放请求是否建立会话、代理是否启动、电视是否回执、错误分类和详细原因没有形成一条可读链路。
- 直播开播检查、视频目标检查、节目单唤醒和开播监控失败存在静默路径。
- 导出文件只有配置和一行行旧日志，用户必须导出后才能查看，不方便现场定位。

## 新诊断记录

`Store` 新增独立、持久化的 `diagnostics.json`，最多保留 300 条结构化事件。每条事件包含时间、模块、动作、状态、摘要、详情和耗时；状态分为进行中、成功、未确认、失败。

当前会记录：

- 导入：收到的输入、识别完成/异常、导入数量、视频/直播目标、解析步骤和耗时。
- 直播播放：房间号、开播检查结果、人气、未开播或接口异常。
- 视频与合集播放：BV、标题、集数、播放会话、代理地址和电视 ADB 配置。
- 播放反馈：代理启动、等待电视、电视接受起播命令、错误分类、自动恢复条件与具体错误详情。
- 电视状态变化、用户停止、配置保存/校验失败、自检结果、节目单唤醒失败和直播监控查询失败。

“电视已接受起播命令”表示 ADB 与播放器 Activity 接受了拉起命令；媒体持续可播仍由后续电视探测确认，诊断中会继续记录电视在线/播放状态变化。

## App 内查看

设备页的“诊断”卡片新增“查看诊断”按钮。对话框直接显示当前设备、IP、代理、电视、配置问题和最近 150 条结构化事件，每条都能看到状态、目标、结果、错误详情与耗时。

对话框支持：

- 导出：生成包含完整运行环境、配置、结构化事件和最近 500 行原始日志的诊断包。
- 清空记录：清空结构化事件、旧执行记录和日志文件，不影响电视配置和内容库。
- 关闭：返回设备页。

设备页仍保留“导出诊断”快捷入口。导出的诊断包新增 SDK、电视在线/在播状态、配置问题、内容库数量、最近播放内容以及结构化事件区块。

## 版本与验证

版本升级为 `3.0.0-alpha.4` / versionCode 6，配置 schema 与 core API 版本保持 1。

回归测试覆盖：

- 结构化事件跨 Store 重建仍可读取，并保留状态、目标和耗时。
- App 内诊断对话框能显示导入成功和电视播放回执。
- 清空诊断不会删除内容库。
- 导出文件包含运行环境和结构化事件。
- 原有配置、ADB、自检、屏幕适配及播放逻辑回归。

2026-11-21 验证结果：核心 191 项、Android 16 项全部通过，无失败、错误或跳过；APK 构建成功并通过签名校验。
