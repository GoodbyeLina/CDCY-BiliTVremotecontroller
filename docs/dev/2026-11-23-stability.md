# alpha.6 媒体稳定性与诊断增强

## 范围

版本 3.0.0-alpha.6 / versionCode 8，保留 alpha.5 的粘贴、ADB 自检复用、直播允许列表和禁止全局媒体键修复。视频解析与电视遥控器操作路径不变。目标是更可观察、有限自愈与保护用户停止/点播进度，不承诺任何网络下零卡顿。

## 可观察内容

- 安全媒体事件：请求、上游 HTTP 响应、首批数据、周期传输量/速度、结束、失败、有限重试。带请求编号和房间号/BV，不记录签名直链或原始网络异常消息。
- HEAD 请求明确标记，不冒充实际媒体首字节或完整传输。
- 手机默认网络类型变化与电视 ADB 定期采样。不是主动测速，不代表局域网质量。
- 诊断界面及导出包含媒体状态；应用与诊断版本标记统一。
- 错误分为播放地址解析、来源连接、来源读取、HTTP 拒绝、电视关闭连接、主动取消等，并附普通用户可执行的建议。

**重要边界：** socket 已写入的数据量不等于电视收到或解码出的帧；首字节不等于首帧；连接 EOF 不等于节目自然播完。没有流量可能是预缓冲、暂停或拖动，不据此强制重启。旧导出仍包含原配置、局域网 IP、内容标题等个人信息，公开分享前请检查；新增媒体事件安全不代表整个导出已统一脱敏。

## 安全恢复

- 仅电视媒体响应头尚未提交前，临时网络错误/408/429/5xx最多额外重试两次，采用短退避；403/410最多重新解析一次。HEAD不自动重试。重试针对同一媒体请求，不重启电视播放器。
- 点播 Range 保留；上游忽略 Range 时本地裁剪。直播不注入 Range，不套用视频镜像策略。
- 传输已开始后的读取中断、电视拖动进度/停止导致的写入断开，不静默从头重播点播。
- 无可靠播放位置证据时，禁用原先按状态时间判定卡顿的看门狗，避免长视频被误重启。
- LIVE 连续三次失联才尝试恢复，累计最多三次并有60秒冷却；VIDEO 连续失联进入错误提示，保护观看进度。ADB失败与进程不存在仍可能受旧布尔探针表示限制，不能据此断言真实播放状态。
- 用户停止使旧异步准备和旧监控查询失效，取消当前媒体连接但保留代理监听；新播放可继续。过期定时器和回调不能继续旧副作用。用户明确允许监控覆盖停止的规则保留，但停止前发出的旧查询不能推翻新停止。

## 真机复测（待执行）

1. 覆盖安装，不先卸载；确认设备页/导出版本是 alpha.6。
2. 普通视频与长视频各播放一次，记录按播放到画面出现的秒数；暂停、快进快退、调音量，不应自动从头播。
3. 新导入正在开播的直播间，检查音画对应；等待10分钟观察，不应因30秒无位置证据而自动重启。
4. 播放准备中立即停止，等30秒；旧准备结果不应再拉起。停止后有旧直播查询返回也不应复活。
5. 暂时断网再恢复，记录提示与重试次数；点播进度不应被自动重置。直播断流后若没有自动恢复，可确认仍开播后手动重试。
6. 异常时尽快导出诊断，并提供发生时间、房间/BV、电视音画和前台应用情况。代理数据正常而电视黑屏仍需要电视端证据。
