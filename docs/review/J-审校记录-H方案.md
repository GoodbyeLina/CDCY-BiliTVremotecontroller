### P0 · 阻断理解（4 条）——已全部修复，见第四节

**P0-1｜合集到底支不支持：需求、计划、验收三处互相矛盾**
- 行号：L282、L293、L686、L708、L721、L748
- 原文：5.1「先查 `series/archives`…返回 -404 再查 `seasons_archives_list` 判合集」；5.1 失败提示「这是合集，暂不支持；请到 UP 空间选『列表』再复制链接」；10.2 M3「链接识别、列表/合集接口…」；10.3 M3「列表与合集接口｜1.0｜两种接口都要」；10.5 #10「粘贴合集链接→明确提示不支持，不崩溃」；MVP 裁剪「M3 的合集接口延后」
- 类型：自相矛盾（范围 + 验收）
- 建议：二选一并全文统一。推荐「识别但不支持」：删 10.2/10.3 的合集接口工作量与 MVP 裁剪说明，保留 5.1 提示与 10.5 #10，FR-09 注明"合集=识别并给出引导"。若改为支持：删「暂不支持」提示、补合集展开/排序/翻页规则、改 10.5 #10 为"合集可轮播"，并实测 `series/archives` 对合集 id 的返回（-404 vs total=0）作为判定信号。

**P0-2｜常驻模式开机后是否需要用户点「开始」**
- 行号：L78、L53、L623、L406
- 原文：FR-11 验收「重启手机后 2 分钟内自动恢复播放」；1.3 验收线「手机重启后，常驻模式能自己恢复」；V-06「解锁后 2 分钟内自动恢复」；而 5.5 启动行写「开机自启 + 用户点开始」
- 类型：自相矛盾（核心行为）
- 建议：5.5 改为「开机自启；解锁后自动恢复上次播放状态（上次为播放中时）；点开始仅用于首次或用户手动恢复」，与 FR-11 / V-06 对齐。

**P0-3｜FR-10「空闲 N 分钟自动停」的"空闲"未定义，默认 10 分钟会掐断正常观看**
- 行号：L77、L407、L439、L453
- 原文：FR-10「无操作 N 分钟（可配）后自动停止」；5.5 停止「点停止，或空闲 N 分钟」；5.6 `IDLE_TIMEOUT`「按需模式的空闲计时」；配置 `idleMinutes` 默认 10
- 类型：歧义（阻断实现）
- 建议：定义空闲＝"持续 N 分钟无播放任务"（未在播放 / 全部不可播 / 处于 Error 且无人重试），并明写"播放中不触发"。

**P0-4｜设计原则 4「不抢控制权」与 TV_LOST 自动恢复、看门狗重启 mpv 直接冲突**
- 行号：L123、L423–425、L437、L475、L814
- 原文：原则 4「用户手动关电视/停播后，系统不自动抢回——这是产品底线」；状态机 `Playing --> Recovering: TV_LOST / PLAY_FAILED`、`Recovering --> Playing: RETRY_OK`；`TV_LOST`＝「adb 超时或 `pidof` 失败」；看门狗「任一异常按重启服务→重连电视→重启 mpv 自愈」
- 类型：自相矛盾（原则 vs 机制）
- 建议：状态机/看门狗区分"用户主动停止"（→ Idle，自愈暂停）与"异常丢失"（自动恢复，设恢复上限与冷却，超限进 Error 等人）；写明"看门狗不覆盖 Idle"。

## 三、总体判断

文档骨架完整、可执行性强。4 个 P0 全部落在**行为定义**而非技术选型（合集范围、常驻启动语义、空闲语义、自愈与不抢控制权）。建议处理顺序：

1. 先修 4 条 P0 + P1-3（直播接口依据）——它们直接影响 M0/M1 写代码时的行为判定；
2. P1-8 的选型回写建议以「H 增一节差异声明」的低成本方式先落地，逐条改写等选型确认后再做；
3. P2 共 20 条多为可测性与措辞，可在 M1 前批量处理。

主会话独立机械校验（编号/日期/端口/版本交叉引用）与上表结论一致，未发现额外问题。
