> **测试版**：本地251项自动化通过；直播音画、长播流畅度与实际起播延迟仍待真机复测。

[下载安装包](../../dist/TVStationRemote-3.0.0-alpha.6-stability.apk) · [日志排查指南](../user/log-troubleshooting.md) · [测试执行 SOP](../testing/alpha.6-test-sop.md)

## 为什么更新

现场alpha.4反馈：视频约5–10秒起播、停止及遥控器可用；直播音画异常；ADB自检超时但实际控制可用；替换导入链接会恢复旧内容。原日志主要证明播放命令提交，缺少实际媒体请求和传输证据。

本次发布包含尚未在主仓库发布的alpha.5修复及alpha.6增强，不能把修复代码风险写成已经证实直播随机音乐的唯一现场原因。

## 修复与新增

### 现场问题修复（alpha.5，纳入本版）

- 导入草稿实时同步，避免定期刷新恢复旧链接或破坏粘贴焦点。
- 自检复用同目标ADB传输层，不因独立检查失败覆盖正常服务状态；超时增加握手阶段信息。
- 新直播会话及时同步代理允许列表。
- 删除起播后盲发全局播放/暂停键，避免暂停mpv或唤醒其他音乐应用。

### 新增诊断（alpha.6）

- 媒体请求、HTTP响应、首字节、累计字节/平均速率/耗时、结束/错误/重试事件。
- 请求编号及安全房间/BV标识，不记录签名播放直链或原始网络异常消息。
- 来源解析/连接/读取、HTTP拒绝、客户端关闭、主动取消分类及中文处理建议。
- 手机默认网络类型变化与电视ADB定期采样；不等于主动测速。
- 应用与诊断版本标记统一为alpha.6，versionCode 8。

### 更安全的恢复

- 响应提交前，适合的临时错误最多额外重试两次；403/410最多重新解析一次地址；HEAD不重试。
- 保留点播Range、本地裁剪与直播无Range边界。
- 已开始传输后的断流不静默从头重播点播；停止/快进导致断开不一律认定故障。
- 无可靠播放位置证据时不按时间误判卡顿、强制重启。
- 直播连续三次失联才尝试恢复，累计上限三次、60秒冷却；点播保护进度并提示。
- 停止使旧异步准备、监控查询和旧定时回调失效，取消当前媒体传输但保留监听。

## 新日志怎么读

**播放请求 → 电视接受命令 → 电视请求媒体 → 来源响应 → 首批数据 → 持续传输**

同一媒体“请求 #编号”串起来读。接受命令不是已显示画面，首字节不是首帧，有传输速度不是一定流畅，EOF不等于整部视频结束。详细原因和逐项检查见[用户指南](../user/log-troubleshooting.md)。

## 验证与限制

- core：218项；App：33项；合计251通过，0失败/错误/跳过。
- `:app:assembleDebug`及最终增量构建成功。
- 覆盖socket真实传输、有限重试、Range、断流不重开、取消/关闭、停止竞态、未知状态不误重启。
- 尚无本版真实电视验收；不宣称已改善起播秒数或解决所有卡顿。
- 代理字节无法证明电视缓冲、解码及画面；ADB布尔探针仍不能精准区分所有失联原因。
- 完整导出仍可能含配置、IP、标题、分享输入；公开上传前检查隐私。

建议同签名覆盖安装，不先卸载；保留配置与内容库。Debug签名测试包，不是正式生产签名版本。
