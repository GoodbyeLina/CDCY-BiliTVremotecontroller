## 2. 划分依据：五条约束 → 五条原则

| 现实约束 | 由此产生的原则 |
| --- | --- |
| 电视不在我手上，在别人那里 | **原则 1：阶段出口不得依赖真机**。能靠 L1/L2 判的不算真机项；只能真机判的进 R 清单 |
| 多人协作，中途会换人 | **原则 2：每个阶段结束都是可交接点**。交接包四件套齐了才算完：可运行产物 + 冻结契约 + 实测记录 + 下一步清单 |
| 二代已在电视上跑通 | **原则 3：先吃存量再写新代码**。二代 config、mpv Activity 名、keyevent 序列、网络拓扑、代理补头与 CDN 镜像，都是已验证事实 |
| 不写代码，先定阶段 | **原则 4：阶段按「可独立验收」切，不按「功能列表」切**。所以 S0 是准备、S5 是收口 |
| 文件多、易「以为没有其实有」 | **原则 5：事实优先、可回溯**。每条任务必须能指到二代码行号或文档行号（本文件用 F／D／G 编号），禁止凭印象排期 |

**为什么不沿用 H 的 M0–M5**：M0–M5 按功能切（探针→骨架→直播→录播→常驻→交付），前提是「电视在手边、单人开发」。现在两个前提都变了，所以前置 S0 收拢环境与存量，并把验证从最后一道关拆成贯穿三层。

## 3. 全文件盘点（结论）

96 个文件全部纳入，逐项作用见 **K1-事实清单-全文件盘点.md**。分布：项目文档 4、ui参考 2、调试手册 6、二代 termux-port 19、二代 android-app 16、归档 3、同源副本 37。**无未读文件。**

三条与排期直接相关的盘点结论：

1. **薄壳 APK 无任何可复用业务逻辑**：42,686B，12 条目，无 lib/ 无 assets，只有 classes.dex + classes2.dex + 资源（K1 §7）。壳的全部能力是「WebView 加载 127.0.0.1:8098 + 一次 HTTP 探活」。复用的是**视觉与文案资产**（图标/主题/20 条字符串/三态骨架），不是代码。
2. **二代 Python 才是功能本体**：19 个文件、约 3,300 行可直接对照实现（control.py 1109 / station.py 830 / install 258 / web 1523）。三代是「用 Kotlin 重写这 3,300 行的语义」。
3. **手册的「验证」不能当已验证**：全流程调试手册附录 B 17 项全 ☐，无一实测记录；H 的 V-01~V-12 同样零记录。任何「已通过」的说法在拿到 R 轮次证据前都不成立。

### 6.3 S0 必须裁决的两件事（否则 S1 返工）

1. **主色（G-16）**：**取 #fb7299 为品牌主色**（图标与既有主题已按此做，用户已认这个粉）；UI 参考的蓝 #2f63ff 降为次要强调色，仅用于链接与可交互高亮；状态色沿用 green #0f9d58 / amber #c77700 / red #e03e46。

   **端口模型裁决（P0-3，消除「单端口」与「双监听面」的矛盾）**：候选 A（8100 控制回环 + 8101 媒体对外）与候选 B（单端口 0.0.0.0 + token）都不采纳——三代 App 是**单进程**，UI、状态机、代理在同一个进程里，控制指令走**进程内方法调用**（PlaybackEngine 的 start/stop/retry），根本不存在 HTTP 控制面。因此定稿：

   - **唯一监听 = 媒体代理 `0.0.0.0:8100`**，供电视拉流；
   - **控制面无端口**（F-14 的「控制面仅回环」是二代双进程架构的事实，三代不继承）；
   - 回环绑定仅用于测试（MiniHttpServer 的 bindAddress 参数）。

## 8. 远程真机协作（贯穿 S0–S5）

### 8.1 对方只做四件事

1. 装 APK（或让我方 adb install 到那台宿主手机）；
2. 打开 App；
3. 双击 collect.bat / collect-macos.sh；
4. 把生成的 zip 发回。

### 8.2 交付包（我方 → 对方）

    tvrc-<versionCode>-<date>/
      app-debug.apk          固定 keystore、versionCode 递增（覆盖安装不冲突）
      SHA256.txt
      README-操作卡.md        三步图文（LF 换行）
      collect.bat / .sh      双击采集
      CHECKLIST-<轮次>.md     本轮 3–5 条待验项
      变更点.txt              3 行以内

### 8.3 回传包（对方 → 我方）

    evidence-<versionCode>-<timestamp>/
      meta.json        机型 / Android 版本 / 电视型号 / WiFi SSID / 时间戳 / 网络形态
      logcat.txt       adb logcat -d
      dumpsys.txt      media_session + activity
      screen.png / *.mp4
      bench.json       代理端口可达性 / adb 版本 / 命令返回

### 8.4 五条纪律

- 固定签名 + versionCode 递增，否则每次卸载重装，配置丢失、升级路径测不出来；
- 每轮只验 3–5 项，一次验一堆失败就无法归因；
- 没有 meta.json 的截图不算证据（无法回溯机型/版本/时间）；
- 一次失败先看日志定位再发新包，不把对方当无意识测试机；
- 对方的失败也是数据（装不上、弹窗看不懂、网络不通都是手册要解决的内容），一律记入 C-实测记录。
