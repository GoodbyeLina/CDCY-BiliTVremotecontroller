# 把轮播台做成“手机 App”的设计反馈

> **0.2.0 已实现**：原生环境检查（Android/Termux/Termux:Boot/后端）+ 网页 5 步向导（手机 IP → 电视扫描 → mpv → 直播间 → 完成）、单项修改、重新初始化、启动健康检查。
> 仍待做：视频/合集/BV（第二版）、完全独立 APK（路线 C）。
>
> 先给结论：**能做，但“真 App”有三种做法，工作量差很多。**
> 建议先做“本地网页控制台 + 添加到主屏幕”，它已经有 80% 的 App 体验；确认好用后，再包一层 APK。

---

## 0. 已确认的需求（2026-11-05）

| 项目 | 你的选择 | 对设计的影响 |
|---|---|---|
| 输入方式 | **UP 名字搜索 + 链接兜底** | 要接 B 站搜索接口、候选列表、格式错误提示 |
| 直播 | **一次只播一个直播间，随时可切换** | 新增 `single` 模式，禁用 30 秒自动轮换；切换时重启或热切换 |
| 视频 | 指定 UP 的**某一些视频**自动播放 | 需要“搜 UP → 列视频 → 多选 → 播放队列”；第二阶段做 |
| 合集链接 | **`lists/<id>` 和 `collectiondetail?sid=` 两种都支持** | 要写两个 API 适配：series + season |
| 单个视频 | **需要** | 支持 BV 号直接入队播放 |
| App 形态 | 待定（见下面“路线 A/B/C”的直白解释） | 决定是先做网页版还是 APK |
| 使用范围 | 先自己用，后续考虑推广 | 后端 API 要可复用；推广时再解决安装门槛 |

### 输入框的反馈规则（你要求的）

输入框下面固定放一行灰色提示，例如：

```
[ 输入 UP 名字，或粘贴直播间/合集/视频链接... ]
支持：UP 名字（如“某某某”）、直播间链接（https://live.bilibili.com/5017134）、
      合集链接（https://space.bilibili.com/23191782/lists/1424266）、
      视频链接（https://www.bilibili.com/video/BV1xx411c7XX）
```

出错时，在输入框下方用红字给出“**错在哪 + 正确格式 + 例子**”：

| 情况 | 提示文案示例 |
|---|---|
| 空输入 | 先输入 UP 名字，或粘贴直播间/合集/视频链接。 |
| 搜不到 | 没搜到「某某某」。试试完整名字/UID，或直接粘贴直播间链接，例如 `https://live.bilibili.com/5017134`。 |
| 同名太多 | 找到 3 个「某某某」，请点头像/粉丝数选择：… |
| 链接格式错 | 这个链接看不懂。直播间链接要包含 `live.bilibili.com/数字`，例如 `https://live.bilibili.com/5017134`；合集链接要包含 `/lists/数字` 或 `collectiondetail?sid=数字`；单个视频要包含 `/video/BV...`。 |
| 找到了但没开播 | 已找到直播间 5017134，但当前未开播；已设为当前台，开播后自动播放。 |
| UP 没有直播间 | 这个 UP 没有开通直播间；可以改用“视频”模式。 |

## 1. 现在的状态

- 手机上**没有输入界面**。要改内容，只能：
  - 跑 `./set-content.sh`（交互问答），或
  - 手改 `~/tvstation/config.json`，再 `./tvctl restart`。
- `set-content.sh` 只认：
  - 直播间号/直播间链接（`live.bilibili.com/<数字>`）
  - 合集/列表链接（`space.bilibili.com/<mid>/lists/<id>`）
- **不认 UP 名字**，也不认单个视频 BV。

## 2. 三种“App 化”路线

### 先用大白话解释 A / B / C

| 路线 | 像什么 | 你要做什么 | 朋友要做什么 | 适合 |
|---|---|---|---|---|
| A 网页版 | 像把“淘宝网页”添加到手机桌面：桌面多一个图标，点开是全屏网页 | 不用装 APK；打开浏览器/桌面图标就能用 | 也要装 Termux，再用浏览器打开 | 你自己先用、快速试 |
| B 真 APK（薄壳） | 像装微信一样装一个 `.apk`，应用列表里有图标 | 发一个 APK 给朋友 | 装 APK + 装 Termux，两边都要 | 想有“真 App”的感觉 |
| C 完全独立 APK | 像装一个普通 App，装上就能用 | 发一个 APK | 只装这一个 APK，不碰 Termux | 真正推广给普通人 |

> 关键区别：**A/B 都还要 Termux 在后台跑**；只有 C 是“一个 App 全包”。
> C 最理想，但要把 Python、adb、代理、开机自启全塞进 APK，工作量 2–4 周，风险也最高。

### 路线 A：本地网页控制台（PWA）——推荐先做

- Termux 里再跑一个小 HTTP 服务，只监听 `127.0.0.1:8098`。
- 手机浏览器打开 `http://127.0.0.1:8098`，加到主屏幕，就有图标。
- 页面功能：
  - 输入 UP 名字 → 搜索 → 选直播间
  - 或粘贴直播间/合集链接
  - 当前轮播列表，增删
  - 开始/停止/唤醒/切 live-video
  - 看状态和最近日志
- 优点：不用 Android Studio、不用签名、改起来快；和现有 `station.py` 共用配置。
- 缺点：本质还是 Termux + 浏览器；没有原生推送。
- 工作量：简单版 1–2 天；带 UP 搜索/合集选择 3–5 天。

### 路线 B：原生 APK（薄客户端）

- Kotlin/Java 写一个真 App，界面原生；后台还是 Termux 的 `station.py`。
- App 通过本地 HTTP 调后端；可以用 `RUN_COMMAND` intent 启停 Termux 服务。
- 优点：真图标、通知、体验好。
- 缺点：要 Android Studio、签名、适配后台限制；Termux 仍要装。
- 工作量：3–7 天。
- 适合：你自己长期用，且不介意维护两个部分。

### 路线 C：完全独立 APK（不装 Termux）

- 把 Python、adb、代理、守护进程、UI 全塞进一个 APK。
- 难点：
  - Android 10+ 对“执行自己目录里的二进制”有限制，adb 要按 `lib*.so` 方式打包；
  - adb key、USB/网络调试授权、后台前台服务、开机自启、电池优化都要自己做；
  - Python 运行时（Chaquopy）会让包大几十 MB；
  - 旧手机 32 位/性能/兼容性；
  - B站接口风控不变，仍然要维护。
- 工作量：2–4 周，风险高。
- 不建议作为第一版。

## 3. “只输入 UP 名字”需要什么

B 站没有“名字 → 直播间”这一步的公开稳定接口，需要：

1. 用搜索接口按名字搜用户：
   `x/web-interface/search/type?search_type=bili_user&keyword=...`
2. 同名/相似名字很多，必须让用户**选人**（头像、mid、粉丝数）。
3. 用 mid 换直播间号：
   `x/live.bilibili.com/room/v1/Room/getRoomInfoOld?mid=<mid>` → `roomid`
4. 搜索接口可能需要 `wbi` 签名 / buvid cookie，风控会 412。
5. 兜底：让用户直接粘贴直播间链接，100% 可靠。

所以 App 的输入框最好做成：

```
[ 输入 UP 名字 ]  [搜索]
  结果：○○○  mid=123  粉丝 1.2万  [选这个]
  或：粘贴直播间链接 https://live.bilibili.com/...
```

### 视频合集更麻烦

- 一个 UP 可能有很多合集/列表，光有名字不够。
- 当前代码只认 `space.bilibili.com/<mid>/lists/<id>` 这种 **series 列表**。
- 如果你拿到的是 `channel/collectiondetail?sid=...` 这种“合集”，当前代码不认，需要另写一个 API 适配。
- 单个视频 BV 当前也不支持。

## 4. 后端接口草图（路线 A/B 共用）

```
GET  /api/state          -> {mode, rooms, list_mid, list_id, tv, public_host, running, current}
POST /api/content        -> {mode:"live", rooms:[...]} 或 {mode:"video", list_mid, list_id}
POST /api/control        -> {action:"start"|"stop"|"restart"|"wake"}
GET  /api/search?q=名字   -> [{mid, uname, fans, roomid, live}]
GET  /api/log?n=50       -> 最近日志
```

后端写 `config.json` 后重启 `tvstation`（或让 station.py 监听配置变化，热切换）。

---

## 5. 安全

- 控制台必须只监听 `127.0.0.1`，不要 `0.0.0.0`；否则同一 WiFi 的人都能改你的台。
- 8099 代理仍然要对电视开（`0.0.0.0:8099`），但它没有鉴权，只适合家里局域网。
- 如果要在外面远程控制，必须加登录/Token + HTTPS/VPN，不建议第一版做。

## 6. 建议的 MVP（最小可用版）

第一版（直播优先）：

1. 首页：状态卡（电视在线/离线、当前房间、是否开播）+ 开始/停止/唤醒。
2. 内容页：
   - UP 名字搜索 → 候选列表（头像、mid、粉丝数）→ 选一个
   - 或粘贴直播间链接
   - 输入框下面固定放格式提示；出错时红字给“错在哪 + 正确格式 + 例子”
   - 选中后设为“当前直播间”，**不自动轮换**
3. 切换：换一个直播间 → 保存 → 重启 station（先接受 3–5 秒黑屏；以后可做热切换）。
4. 设置页：电视 IP、手机 IP、端口。
5. 日志页：最近 50 行。

第二版（视频）：

6. 合集链接：`lists/<id>` 和 `collectiondetail?sid=` 两种都认。
7. 单个 BV：粘贴视频链接直接播。
8. 指定 UP 的某些视频：搜 UP → 列视频 → 多选 → 按顺序/随机自动播放。
